# UI/UX 설계 v0.1: 기본 UI/UX 갖추기

> 2026-11-19. 프로토타입(`scripts/proto/`)과 디자인 팩(`assets/original/mibangsong/`)을 기준으로, 게임에 기본으로 필요한 UI/UX 가운데 있는 것과 없는 것을 가르고, 화면별 설계와 그림 목록, 구현 순서를 정합니다.
> 이 문서는 공개 저장소에 있으므로 줄거리·대사·엔딩 내용은 쓰지 않습니다. 대사 표기·길이·읽는 시간 규칙은 비공개 스타일 가이드(v1.2)에 있고, 여기서는 화면에 그 규칙을 담는 방법만 다룹니다.
> 근거 표시: **[확인]** 원문을 열어 확인, **[약함]** 검색 요약이나 간접 인용, **[추론]** 근거 수치에서 끌어낸 판단.

## 0. 원칙

1. **UI는 세 겹이다.** 화면마다 어느 겹인지 먼저 정하고, 겹마다 생김새를 섞지 않는다.

   | 겹 | 어디서 | 생김새 | 지금 있는 것 |
   |---|---|---|---|
   | **테이프 속(1998)** | 테이프 재생 중 | 촬영한 카메라의 화면: 뷰파인더 모서리, REC, 타임코드, 트랙 배지, VHS 질감. 3x5 픽셀 숫자 | 뷰파인더, 배지, 타임코드, VHS 셰이더, 목소리 파형 상자 |
   | **작업실(2026)** | 테이프 사이, 추리 보드, 문서 | 디지털화 작업용 프로그램 화면: 파형, 타임코드 축, 카드, 메신저 창 | 작업실 그림, 추리 보드, 장면 속 작은 창(메신저·통화·캡처 로그) |
   | **게임 밖(메뉴)** | 타이틀, 일시정지, 설정, 확인 창 | **읽기 쉬움이 먼저.** 이야기 소품처럼 꾸미지 않는다. 같은 패널 나인슬라이스와 커서를 쓴다 | 타이틀, 일시정지, 설정, 새 게임 확인 |

2. **글은 읽혀야 한다.** 기본 글자 크기, 배경 대비, 읽는 시간은 플레이어가 바꾸지 않아도 기준을 넘는다(1절 P0-2). 공포는 UI가 아니라 장면이 만든다.
3. **게임을 하는 입력으로 모든 UI를 쓴다.** 키보드만 되는 메뉴, 마우스만 되는 보드를 만들지 않는다 [확인: Game Accessibility Guidelines 기본 항목 「Ensure that all areas of the user interface can be accessed using the same input method as the gameplay」].
4. **핵심 정보를 색이나 소리 하나에만 싣지 않는다.** 트랙은 배지 색(자홍·청록)과 글자(LINEAR·HI-FI)를 함께 쓰고, 소리로만 전해지는 단서는 소리 자막으로도 보인다 [확인: 같은 지침 「Ensure no essential information is conveyed by a fixed colour alone」, 「…by sounds alone」].
5. **스케어 직전에는 UI가 소리를 내거나 움직이지 않는다.** 30~500 ms의 앞선 자극이 놀람을 약하게 만든다는 설계 규칙(`docs/scare-director.md`)이 알림, 저장 표시, 버튼 소리에도 걸린다. 스케어 디렉터가 대기 중일 때 알림은 미뤄 둔다.
6. **설정은 모두 저장되고, 첫 시작은 짧다.** 첫 실행에서 꼭 물을 것만 묻고 바로 시작한다 [확인: 같은 지침 「Allow the game to be started without the need to navigate through multiple levels of menus」, 「Ensure that all settings are saved/remembered」].

## 2. 필요한 것 (우선순위)

**P0**은 첫 외부 플레이테스트 전에, **P1**은 데모 공개 전에, **P2**는 출시 전에 둡니다.

### P0

**P0-1 입력 정리. (2026-11-19 프로토타입에 들어감, 아래 메모)** 모든 조작을 Godot `InputMap` 액션(`move_left`, `jump`, `interact`, `track_linear`, `track_hifi`, `track_mix`, `rec`, `ff`, `board`, `pause`, `accept`, `cancel`, `menu_*` 등. 저널·대사 기록 액션은 그 화면과 함께)으로 옮긴다. 게임패드 기본 배치를 둔다. 메뉴와 대화는 마우스 클릭으로도 넘긴다. 키 다시 지정 화면(조작 탭)을 둔다 [확인: 같은 지침 「Allow controls to be remapped / reconfigured」]. 화면의 입력 안내는 마지막에 쓴 장치(키보드/패드)에 맞춰 바뀐다.

  - **들어간 것:** `scripts/proto/proto_input.gd`(액션 26개, 다시 지정할 수 있는 것 12개), 설정의 「조작 바꾸기」 화면(겹치면 서로 바꿈, 기본값으로, `[input]` 섹션에 저장), 마우스(메뉴·설정·선택지 가리키기와 클릭, 대사 넘기기, 오른쪽 클릭 = 뒤로), 패드 버튼은 위치 이름(「아래 버튼」), 안내 문구의 `{action}` 자리표시자. 런타임 테스트 `tests/godot/test_proto_input.gd`(41개), 데모 봇이 조작 화면을 거침. 합성 마우스·키·패드 입력으로 타이틀·일시정지·설정·조작 화면을 따로 확인함.
  - **남은 것:** 입력 안내를 글자 대신 아이콘으로(`mbs_ui_glyphs`), 추리 보드의 마우스 조작. (빨리 감기 누르기/누르고 있기 전환은 P0-8로 들어감.)

**P0-2 글자 크기와 배경. (2026-11-19 프로토타입에 들어감, 아래 메모)** 바꾸기 전 대사 20px, 자막 20px, 말풍선 18px(1280x720 기준)은 1080p로 환산하면 27~30px이다. Xbox 자막 지침은 1080p에서 46px 이상, 한 줄 40자(영문) 이하, 2줄, 배경 불투명도를 플레이어가 0~100%로 고르게 한다 [확인: XAG 104, 앞선 조사 노트]. 기본값을 1280x720 기준 **대사·자막 30px, 말풍선 28px, 이름표 26px**으로 올리고(1080p 약 45px), 글자 크기 단계는 **0.85·1.0·1.2·1.4배** 넷으로 넓힌다. 자막과 말풍선 뒤에 **배경 상자(불투명도 0·50·75·100%, 기본 75%)**를 둔다 [추론: 46px 환산과 화면 폭 1075px에서 대사창 한 줄 약 35자, 말풍선 한 줄 약 17자가 되어 스타일 가이드 v1.2의 길이 목표와 맞음].

  - **들어간 것:** 1280x720 기준 대사·자막 30px, 말풍선 28px, 이름표 26px, 선택지 26px, 입력 안내 20px, 문서 본문 24px·제목 30px, 작업실 글 26px, 타이틀 메뉴 28px. 글자 크기 넷(작게·보통·크게·아주 크게 = 0.85·1.0·1.2·1.4배). 자막과 말풍선은 **글 길이에 맞춘 상자**(가장 긴 줄 폭, 자막은 화면 폭의 80%·말풍선은 40%까지, 넘으면 단어 사이에서 줄바꿈) 위에 뜨고, 상자 불투명도는 0·50·75·100%(기본 75%). 대사창·선택지·자막·말풍선 모두 한국어를 어절 사이에서만 줄바꿈한다(전에는 대사창이 「대사창 / 과」처럼 음절에서 끊었다). 자막은 대화창이 열려 있으면 창(과 목소리 파형) 바로 위로, 닫혀 있으면 타임코드 위(화면 높이 86%)로 간다. 대화창이 선택지 넷으로 높아져 자막이 위로 올라가면 말풍선이 그 위로 비킨다. 타임코드는 카메라 그림의 일부라 글자 크기 설정을 따르지 않는다.
  - **확인:** 실제 렌더링한 화면(대사창, 자막·말풍선, 가장 큰 글자에 배경 100%, 선택지 넷과 긴 선택지)으로 겹침과 줄바꿈을 보고, 합성 입력 점검(59개 항목)에서 크기(30px, 1.4배에 42px), 말풍선 폭(짧은 것 105px, 긴 것 512px에서 두 줄), 가운데 맞춤, 자막이 창과 타임코드 위에 있는지를 숫자로 확인함.
  - **남은 것:** 배경 상자를 그림(`mbs_ui_text_bg`)으로 바꾸기. 개발용 상태 줄은 큰 글자에서 말풍선과 겹칠 수 있다(P0-3에서 없앰). 대화창은 선택지 넷이면 화면 절반 가까이 올라온다. 플레이테스트에서 선택지 글자(26px)를 줄일지 본다.

**P0-3 테이프 상태 표시(데크 HUD).** 개발용 상태 줄을 없애고, 1998 겹의 카메라 화면과 2026 겹의 데크 사이에 **작은 데크 패널**을 둔다: 트랙 스위치 세 칸(LINEAR·HI-FI·MIX, 지금 칸이 눌림, 잠긴 칸은 자물쇠), 테이프 카운터(재생 횟수 「재생 7」, 3x5 숫자), 배속 표시(▶▶). 평소에는 접혀 있다가 트랙을 바꾸거나 배속을 바꿀 때, 작업실에 있을 때 펼친다. 뷰파인더(REC·타임코드·배지)는 카메라의 것이라 그대로 두고, 카메라를 끈 뒤에는 데크 패널만 남는다.

  - **들어간 것 (2026-11-20):** `scripts/proto/proto_deck.gd`. 타임코드와 같은 줄, 그 왼쪽(카메라를 끈 뒤와 작업실에서는 그 자리)에 둔다. 펼치면 스위치 셋(LINEAR·HI-FI·MIX, 지금 트랙은 트랙 색으로 눌려 들어간 모양, 다른 칸은 튀어나온 모양, 잠긴 칸은 자물쇠와 흐린 글자), 「재생 n」, 빨리 감기 표시(삼각형 둘, 빠를 때 「x4」)와 각 키 안내(마지막에 쓴 장치 기준). 접으면 지금 트랙 칸 하나(빠를 때는 빨리 감기 표시도)만 보인다. 테이프가 시작될 때, 트랙이나 배속이 바뀔 때(이야기가 트랙을 바꿀 때 포함) 3초 펼치고, 작업실에서는 늘 펼친다. 잠긴 트랙을 누르면 바뀌지 않고, 데크가 펼쳐지며 그 칸 테두리가 1.5초 주황색이 되고(깜박이지 않음), 「HI-FI 잠김」 또는 「지금은 MIX로 바꿀 수 없습니다」(잠금 규칙)를 띄운다. 대화창이 열려 있으면 평소에는 창 아래에 가려지고, 바뀐 직후에만 창 오른쪽 위로 올라온다. 그때 자막은 데크 위로 비킨다. 문서가 열려 있으면 숨는다. 지금 재생 중인 트랙에는 잠겨 있어도 자물쇠를 그리지 않는다(이야기가 잠긴 트랙으로 바꿀 수 있음). 개발용 상태 줄은 `-- --debug-hud`로 실행할 때만 보인다. 새 문자열: `ui.deck.counter`, `ui.deck.locked`, `ui.deck.held`.
  - **확인:** 실제 렌더링한 화면 여덟 장(작업실, 테이프 시작, 접힘, 잠긴 트랙, 빨리 감기 펼침·접힘, 대화 중 트랙 바뀜, 패드 키 이름)과 헤드리스 점검 22개(타이틀에서 없음, 문서 아래에서 없음, 타임코드 왼쪽 같은 줄, 3초 뒤 접힘, 잠긴 트랙이 안 바뀜, 대화창 위로 올라왔다가 다시 숨음 등).
  - **남은 것:** 데크 그림(`mbs_ui_deck`)과 3x5 숫자로 바꾸기. 패드에서는 키 이름(「왼쪽 어깨」)이 길어 펼친 데크가 화면 폭의 절반쯤 된다. 입력 안내 아이콘(`mbs_ui_glyphs`)이 오면 줄어든다. 화면 오른쪽 위의 개발용 알림(토스트)은 P0-6에서 알림으로 바꾼다.

**P0-4 저널(기록철).** 주운 문서를 다시 보는 화면. 분류 탭(제작 문서 / 마을 / 채록 / 기록관 / 메모), 목록 줄(제목, 주운 테이프 시각, 새 표시), 오른쪽에 지금 문서 뷰어(종이 패널 재사용). 작업실과 일시정지 메뉴에서 연다(J 키 / 패드 메뉴 버튼). 보드 카드의 근거 문서로 바로 가는 링크를 둔다. 런타임에는 이미 `collected_docs(category)`가 있다(`docs/script-format.md`).

  - **들어간 것 (2026-11-20):** `scripts/proto/proto_journal.gd`. 분류 탭은 레벨 파일의 `journal` 블록(`{"tabs": [{"label", "categories"}]}`)에서 오고, 없으면 「전체」 한 탭이다. 왼쪽 목록은 제목(길면 말줄임), 주운 테이프 시각(작업실에서 주웠으면 「작업실」), 아직 여기서 보지 않은 문서에는 주황 네모 점. 탭 이름 옆에 안 본 수. 오른쪽은 종이 패널에 본문(마우스 휠로 스크롤). 확인을 누르면 원래 문서 보기로 크게 열리고, 닫으면 기록철로 돌아온다. J 키(패드: 왼쪽 스틱 누르기), 일시정지 메뉴 「기록철」, 작업실 안내 줄 「기록철 [J]」로 연다. 테이프와 작업실 어디서든(대화 중 포함) 열리고, 열려 있는 동안 게임이 멈춘다. 일시정지 메뉴에서 열었으면 닫을 때 그 메뉴로 돌아온다. 주운 시각과 본 표시는 저장 파일의 `journal`에 들어간다(형식 번호는 그대로, 없으면 빈 것으로 읽음). 공개 데모는 「전체」와 「메모」 두 탭.
  - **확인:** 실제 렌더링 화면(기록철, 다음 탭, 크게 보기, 일시정지 메뉴)과 점검 16개(J로 열림, 탭 다섯, 크게 보기에서 돌아옴, Esc로 닫힘, 일시정지 메뉴에서 열고 돌아옴, 저장에 들어감 등). 데모·비공개 봇이 탭을 모두 넘기고 문서 하나를 크게 열었다 닫는다.
  - **남은 것:** 보드 카드의 근거 문서로 가는 링크(`ui.journal.to_board`), 서류철 그림(`mbs_ui_journal`), 키보드·패드로 긴 본문 스크롤(지금은 크게 보기나 마우스 휠).

**P0-5 대사 기록(백로그).** 음성이 없는 추리 게임이라 지나간 대사를 다시 읽을 곳이 필요하다. 이번 테이프(루프)와 지난 작업실의 대사를 시간 순으로, 화자 이름표·테이프 시각과 함께 보여 준다. 선택한 줄은 표시한다. 스크롤과 장면 단위 건너뛰기. 대사 진행 중 L 키(패드: 왼쪽 숄더)로 연다. 대사 기록은 저장하지 않고 루프가 바뀌면 지난 루프 기록은 접어 둔다 [추론].

  - **들어간 것 (2026-11-20):** `scripts/proto/proto_log.gd`, 화면 이름은 「지난 대사」. 대사창 줄(화자 이름), 고른 답(「고른 답」, 하늘색), 자막 큐 줄(흐린 글자)을 차례로 쌓고, 대화가 시작될 때마다 「재생 n 테이프 시각(또는 작업실)」 머리줄을 넣는다. 지금 재생은 다 보이고 지난 재생은 「+ 재생 n · m줄」 한 줄로 접혀 있다가 확인으로 펼친다. 위·아래 한 줄, 좌·우 장면, Page Up·Tab 한 쪽, 마우스 휠. L 키(패드: 오른쪽 스틱 누르기)와 일시정지 메뉴 「지난 대사」로 열고, 대화 중에도 열린다. 대사창 안내 줄에 「지난 대사 [L]」을 붙였다. 패드의 왼쪽 숄더는 대화 중 트랙 바꾸기(LINEAR)에 쓰여 이 설계안과 달리 스틱 누르기로 했다. 저장하지 않고, 이어하기와 새 게임에서 비운다. 3000줄을 넘으면 오래된 것부터 버린다.
  - **확인:** 실제 렌더링 화면(지난 재생 접힘·펼침, 맨 아래 줄까지 스크롤)과 점검(L로 열고 닫힘, 접힌 재생 펼치기). 화면을 보다가 새 줄이 배치되기 전에 스크롤해 마지막 줄이 잘리던 것을 고쳤다(한 프레임 뒤에 스크롤).
  - **남은 것:** 바크(말풍선)는 넣지 않았다. 화자 이름표 색을 인물별로 나눌지, 장면 머리줄에 장소 이름을 붙일지는 플레이테스트에서 본다.

**P0-6 알림과 저장 표시.** 대화에 섞인 `system` 안내(「추리 보드에 카드가 꽂혔습니다」 같은 것)를 대화 밖의 **알림**으로 옮긴다: 오른쪽 위에 아이콘(카드·문서·트랙·매듭)과 한 줄, 3~4초, 겹치면 쌓기. 스케어 대기 중에는 미룬다(원칙 5). 자동 저장 중에는 **오른쪽 아래 테이프 감기는 작은 아이콘**을 띄우고, 그동안 끄지 말라는 안내를 설정 화면 도움말에 둔다.

  - **들어간 것 (2026-11-20):** `scripts/proto/proto_notices.gd`. 뷰파인더 배터리 표시 아래(화면 높이 12.8%)에 오른쪽 맞춤으로 쌓인다. 한 줄 글과 그린 아이콘(카드, 매듭, 문서, 트랙, 녹화, 안내)이 붙고, 3.5초 뒤 0.4초 동안 흐려져 사라진다(깜박이지 않음). 넷째가 오면 가장 오래된 것을 접는다. 스케어 디렉터가 조용한 구간이거나 스케어 중이면 새 알림은 기다렸다가 끝난 뒤에 뜬다(원칙 5). 저장 표시도 그동안 숨는다.
    - 게임이 상태를 보고 스스로 띄우는 것: 보드 카드가 꽂힘(카드 문서 제목), 매듭이 풀림, 트랙이 열림(HI-FI·MIX), 문서를 주움(문서를 닫은 뒤 「기록철에 남김」), 카드가 아닌 녹화 플래그(「녹화했습니다」), 잠긴 트랙을 누름(데크와 함께). 새 게임·불러오기 직후에는 지금 상태를 조용히 받아 적기만 하고 알림을 띄우지 않는다. 개발용 단축키 M·P도 영어 토스트 대신 설정 이름으로 알린다(시작 경고 문서가 이 키를 안내하기 때문). 「RESPAWN」 토스트는 `--debug-hud`에서만.
    - 이야기가 띄우는 것: 새 출력 대상 `[to=notice]`(`docs/script-format.md` 6.3절). 그 줄은 대화창 대신 알림으로 뜨고 대화는 바로 다음 줄로 간다(릴은 제 속도대로). 길이 상한은 프로젝트 파일의 `max_chars.notice`(40자). 공개 데모에 한 줄 넣어 CI가 거친다.
    - 비공개 원고: 「추리 보드에 카드가 꽂혔습니다: …」 다섯 줄과 「데크의 MIX 스위치를 쓸 수 있습니다」 한 줄은 자동 알림이 같은 말을 하므로 뺐고, 「매듭 칸 일곱과 결론 칸 셋이 열렸습니다」는 `[to=notice]`로 바꿨다. 사용법 안내, 콘텐츠 경고, 결론 질문은 대화창에 그대로 둔다.
    - 저장 표시: 자동 저장 때 오른쪽 아래에 「저장 중」과 천천히 도는 릴(초당 1/4바퀴)을 1.6초 이상 띄운다. 설정 화면 아래 안내에 「표시가 보이면 끄지 마세요」를 붙였다.
  - **확인:** 실제 렌더링 화면(작업실 저장 표시, 알림 셋이 쌓인 테이프 화면, 설정 안내)과 점검 13개(시작 때 알림 없음, 카드 알림이 카드 이름을 씀, 문서 알림은 문서를 닫은 뒤, 넷째가 오면 셋 유지, 3.5초 뒤 사라짐, 스케어 중에는 기다림, 저장 표시가 떴다가 사라짐).
  - **남은 것:** 아이콘 그림(`mbs_ui_icons`). 알림 소리는 넣지 않았다(넣으면 원칙 5에 맞춰 같은 대기 규칙).

**P0-7 첫 실행과 경고 다시 보기.** 첫 실행 순서: 언어(번역이 생기면) → 밝기 보정 한 화면 → 시작 경고와 스케어 강도 고르기(한 화면, 기본/약하게/끔 + 번쩍임 줄이기) → 시작. 시작 경고는 타이틀의 옵션 안 「콘텐츠 안내」에서 다시 볼 수 있다(설정집 점검 목록의 요구).

**P0-8 설정 화면을 탭으로. (2026-11-19 프로토타입에 들어감, 표 아래 메모)** 한 목록을 탭 다섯으로 나눈다. 모든 값은 `user://proto_settings.cfg`에 저장한다.

| 탭 | 항목(새것은 굵게) |
|---|---|
| 화면 | **창/전체 화면**, **배율(정수 배수)**, **밝기 보정**, **VHS 질감 세기(끔·약하게·기본)**, **화면 흔들림 끔** |
| 소리 | 전체, 바탕 소리, 효과음, **음악**(음악이 생기면), **소리 자막(P1)** |
| 글 | 글자 크기 넷, 자막 켜기, **자막·말풍선 배경 불투명도**, **화자 이름 보이기**, **글 넘김: 직접/자동(읽는 시간 공식 사용)**, **자동 넘김 속도(느리게·기본·빠르게 = 읽는 시간 ×1.3·1.0·0.8)** |
| 접근성 | 스케어 강도, 번쩍임 줄이기, **추격 보조(추격자 속도 낮춤·잡히면 바로 앞에서 다시)**, 메타 연출 동의 |
| 조작 | **키 다시 지정**, **패드 배치 보기**, **누르기/누르고 있기 전환(빨리 감기)** |

  - **들어간 것:** 탭 다섯(`scripts/proto/proto_settings.gd`). 화면: 창/전체 화면, VHS 질감(끔·약하게·기본, 약하게는 주사선·색 번짐·잡티·트래킹 띠를 절반으로), 화면 흔들림. 소리: 전체·바탕·효과. 글: 글자 크기 넷, 자막, 자막 배경, 말하는 사람 이름(대화창 이름표와 자막 앞 이름), 대사 넘기기 직접/자동(읽는 시간 공식 `reading_secs`, 대사창 줄은 최대 12초, 선택지와 문서에서는 늘 멈춤, 메뉴가 열려 있으면 시계도 멈춤), 자동 넘김 속도. 접근성: 스케어 강도, 번쩍임 줄이기, 추격 보조(추격자 속도 0.7배), 메타 연출 동의. 조작: 조작 바꾸기(패드 배치도 같은 화면에서 보임), 빨리 감기 버튼 「눌러서 켜고 끄기 / 누르고 있는 동안」. 탭은 패드 어깨 버튼, Tab·Page Up·Page Down, 탭 줄에서 좌우, 마우스 클릭으로 바꾼다. 설정 글은 자리가 넘치면 목록이 스크롤된다(조작 화면 14줄). 봇과 릴은 기본값으로 돌고 플레이어의 설정 파일을 읽거나 쓰지 않는다(전에는 릴이 플레이어 설정을 읽었다). 봇이 탭 다섯을 모두 넘기며 값을 바꿨다 되돌리고 탭 줄로 조작 탭에 가는지 확인한다.
  - **남은 것:** 밝기 보정(P0-7 첫 실행 화면과 함께), 배율(정수 배수), 음악 음량(음악이 생기면), 소리 자막(P1-1), 추격 보조의 「잡히면 바로 앞에서 다시」(지금은 속도만), 언어. 설정 화면 글자는 글자 크기 설정을 따르지 않는다(조작 화면이 넘치지 않게 고정, 플레이테스트에서 다시 봄). 탭 모양은 `mbs_ui_widgets` 그림이 오면 바꾼다.

### P1

**P1-1 소리 자막.** 소리로만 전해지는 단서(물, 징, 장구가 멎음, 발전기)를 대괄호 자막으로 띄운다(설정 「소리 자막」). 넷플릭스 한국어 청각장애인용 자막의 효과음 표기를 따라 가능하면 의성어에 출처를 붙이고(`[철썩 - 물가]`, `[징 - 굿청]`), "소리"나 "들린다"는 쓰지 않는다 [확인: 넷플릭스 한국어 가이드 II.9, 앞선 조사 노트]. 화면에 보이지 않는 화자는 같은 가이드 II.8처럼 대괄호 화자 표시(`[여자]`, `[무전]`)를 쓸 수 있다. 스케어 스팅어는 소리 자막을 늦게 띄우지 않는다(놀람을 줄이지 않게 스팅어와 같은 프레임에).

**P1-2 화면 밖 목소리.** 몸이 보이지 않는 목소리는 머리 위 말풍선 대신 화면 가장자리의 방향 표시(`<`, `>`)와 출처 라벨(「물 쪽」, 「무전」, 「전화」)이 붙은 자막으로 띄운다 [확인: XAG 104의 화면 밖 화자 표시, BBC 자막 지침의 전화·확성기 표기]. 목소리 파형 상자는 그대로 함께 쓴다.

**P1-3 막혔을 때.** 작업실에 「할 일」 쪽지 한 장(다음에 볼 곳을 사물로 암시, 정답 아님). 같은 단계에서 루프를 여러 번 넘기면 작업실 인물이 한 줄 힌트를 준다(대사는 비공개 원고에서). 힌트 끄기 설정.

**P1-4 확인 창 하나로.** 새 게임 덮어쓰기, 타이틀로(작업실 이후 진행이 사라짐), 게임 종료, 되돌릴 수 없는 이야기 속 선택을 같은 확인 창 모양으로. 기본 선택은 늘 안전한 쪽(아니요).

**P1-5 본 엔딩 목록.** 타이틀의 「기록」에서 본 엔딩의 칸만 채워 보여 준다(제목·그림 한 장, 내용 없음). 2회차가 열린 것을 표시한다.

**P1-6 용어 강조와 풀이.** 처음 나오는 낯선 말에 색을 입히고(대화창을 `RichTextLabel`로 바꿔야 함: 지금 `Label`은 BBCode 색을 그리지 않는다), 저널에 「말 풀이」 탭을 둔다. 풀이 글은 비공개 원고 쪽에서 자문을 거친 뒤 쓴다.

### P2

**P2-1 조건부 이름표.** 정체가 드러나면 화자 이름표가 바뀐다(스타일 가이드 v1.2 규칙 3). 런타임에 「플래그가 켜지면 이 화자의 표시 이름을 바꾼다」 규칙이 필요하다.

**P2-2 스크린 리더와 메뉴 낭독.** 메뉴 항목과 대사를 운영체제의 화면 낭독기로 읽힐지 검토한다 [미확인: Godot 4.7의 지원 범위는 확인하지 않았다].

**P2-3 수동 저장 칸.** 지금은 작업실 자동 저장 한 칸. 루프 게임이라 필요성이 낮지만, 엔딩을 고르기 전 칸 하나를 따로 둘지 플레이테스트로 본다.

## 6. 구현 순서

1. **입력(P0-1).** 다른 UI가 모두 이 위에 선다. `InputMap` 액션, 패드, 마우스, 입력 안내 전환. 봇과 릴은 액션으로 입력을 흉내 낸다.
2. **글자 크기·배경·설정 탭(P0-2, P0-8).** 기본값을 올리고 저장되는 설정을 넓힌다. (2026-11-19 들어감)
3. **데크 패널(P0-3).** 개발용 상태 줄은 `--debug-hud` 실행 인자로만 보이게 남긴다. (2026-11-20 들어감)
4. **저널과 대사 기록(P0-4, P0-5).** (2026-11-20 들어감)
5. **알림·저장 표시(P0-6).** 대화 속 `system` 안내 줄은 비공개 원고에서 알림 명령으로 바꾼다. (2026-11-20 들어감)
6. **첫 실행과 경고 다시 보기(P0-7).**
7. P1을 플레이테스트 결과 순서대로.

- 그림이 없는 동안은 지금 패널 나인슬라이스와 단색 상자로 먼저 만들고, 디자인 팩 v0.3 그림이 오면 바꿔 끼운다(프로토타입의 `art` 블록 `ui` 항목).
- 새 화면마다 공개 데모 레벨과 봇이 한 번씩 거치게 해 CI가 검사하게 한다(저널 열기, 대사 기록 열기, 설정 탭 넘기기, 알림 하나).
- ACTION GAME MAKER G로 옮길 때 이 화면들은 AGM G의 UI 오브젝트로 다시 만든다. 화면 구성과 문자열 키, 그림은 그대로 쓴다.

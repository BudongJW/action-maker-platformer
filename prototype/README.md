# Prototype

A vertical slice for playtesting the loop, the HI-FI / LINEAR tracks and the jump scares. It is a graybox unless the level file has an `art` block, which swaps the shapes for pixel art from `assets/original/` (see "Art block" below). Code lives in [`scripts/proto/`](../scripts/proto/); [`tools/build_prototype.py`](../tools/build_prototype.py) assembles a standalone Godot 4.7 project in `build/prototype/` (git-ignored) and can run it.

```bash
GODOT_BIN=/path/to/Godot_v4.7-stable python3 tools/build_prototype.py --run
```

| Source | When | Files |
|---|---|---|

The demo is placeholder English text with no game story. The prototype code contains no dialogue text.

## Controls

Every control is an input action (`scripts/proto/proto_input.gd`, `ProtoInput.ACTIONS`) with keyboard and gamepad defaults. Gamepad buttons are named by position (bottom, right, left, top), not by any maker's letters. Hints on screen name the key or button of the device used last.

| Keyboard | Gamepad | Action |
|---|---|---|
| Up / Down, Enter | D-pad or left stick, bottom button | Title screen: Continue (only when there is a save), New Game (asks first when it would overwrite a save), Options, Quit. After the end credits, Enter goes back to the title |
| A / D or arrows | D-pad or left stick | Move |
| Space | Bottom button | Jump |
| W / S | D-pad or left stick up / down | Climb a ladder |
| Enter or E | Bottom button (menus, dialogue), left button (examine) | Advance dialogue, close a document; in the workroom, play the tape; in the tape, examine where a prompt shows |
| 1-4, or Up / Down then Enter | D-pad up / down, bottom button | Choose |
| Z / X / C | Left shoulder / right shoulder / top button | LINEAR / HI-FI / MIX (HI-FI and MIX unlock through the story; a locked one does not switch, and the deck panel marks it) |
| R | Right trigger | Camera REC (records evidence inside an evidence area) |
| F | Left trigger | Fast-forward the tape (x4): each press toggles it, or with the Controls tab's "Hold" it runs while held. It pauses while a scare is pending or relaxing, because the scare director runs in real time |
| M / P | — | Development shortcuts: scare mode (default / soft / off), photosensitivity-safe scares |
| B | Select | Deduction board in the workroom, once the level's `board` block allows it: Left / Right choose, Up / Down change the row (cards, knots, conclusions), B, Select, Esc or the right button closes |
| The level's letter (`hub.actions[].key`) or D | Top button | A workroom action (its prompt string uses `{key}` for the key name) |
| J | Left stick press | Journal: the documents found so far, by section (the level's `journal` block), with the tape time each was found; Up / Down pick, Page Up / Tab or Left / Right change the section, Enter reads it full size, Esc or J closes |
| L | Right stick press | Dialogue log: this session's lines, chosen options and captions, a heading per scene; earlier plays are folded (Enter opens one). Up / Down a line, Left / Right a scene, Page Up / Tab a page. Not saved |
| Esc | Start | Pause menu during play: Resume, Journal, Dialogue Log, People (when the level keeps affinity: everyone met, with portrait and affinity gauge), Options, Back to Title (progress since the last save point is not kept). Options is the settings screen (below) |
| Tab / Page Down, Page Up | Right / left shoulder | Next / previous settings tab (Up from the first row also reaches the tab row, where Left / Right change the tab) |

- **Mouse:** hovering a menu item, a settings row or a choice selects it; a left click picks it, advances dialogue, closes a document or plays the tape in the workroom; a right click goes back (cancel).
- **First run** (`proto_first_run.gd`, docs/ui-ux.md P0-7): until `first_run_done` is in the settings file, two pages come before the title: brightness (three squares on black, clearly visible / barely visible / not visible, and the brightness value) and the content notice (the level's first `start_docs` document) with the scare, reduce-flashing and graphic-content choices. The first new game right after it skips the start document. Both pages open again from the options (Display: Brightness, Accessibility: Content Notice). Bot runs and reels skip the first run.
- **Settings tabs:** Display (window or fullscreen, brightness 0-10 with a calibration page, VHS texture off / soft / default, screen shake), Audio (master, ambience, effects), Text (four text sizes, captions, caption background 0 / 50 / 75 / 100%, speaker names, text advance manual or auto, auto speed), Accessibility (scares, reduce flashing, graphic content shown or veiled, chase assist, effects outside the game window, content notice), Controls (the controls screen below, fast-forward toggle or hold). Values apply at once and are saved in `user://proto_settings.cfg`; bot runs and reels use the defaults and leave that file alone. Auto-advance waits the line's reading time (`ProtoUI.reading_secs`, up to 12 s for a dialogue window line) times 1.3 / 1.0 / 0.8, never moves past choices or a document, and stops while a menu is open.
- **Deck panel** (`proto_deck.gd`, docs/ui-ux.md P0-3), on the timecode's line left of it (or in its place once the camera is off, and in the workroom): the LINEAR / HI-FI / MIX switches (the playing one pressed in, a locked one with a padlock), the play counter and the fast-forward mark, each with its key for the current device. Folded it shows only the current track (and the fast-forward mark while the tape runs fast); it opens for three seconds when the tape starts, the track or the speed changes or a locked track is tried, and stays open in the workroom. While the dialogue window is open it shows only right after a change, above the window. The development status line at the top only appears with `-- --debug-hud`.
- **Notices** (`proto_notices.gd`, docs/ui-ux.md P0-6): one-line messages with a drawn icon at the top right, under the viewfinder's battery mark, for a board card pinned, a knot untied, a track unlocked, a document collected (once it is closed), footage recorded on a flag that is not a card, a locked track tried, and story lines sent with `[to=notice]` (the dialogue goes straight on). They stay 3.5 s and fade, stack three high, and wait while the scare director is quiet or a scare is playing. A new game or a load takes stock silently. The autosave shows "Saving" with a turning reel at the bottom right for at least 1.6 s.
- **Sound captions and off-screen voices** (P1-1, P1-2): with the Audio tab's Sound Captions on, the level's `sound_captions` (`{"sfx:<name>" | "loop:<id>" | "loop_stop:<id>" | "scare:<id>" | "event:<name>": text}`) put bracketed lines under the captions for 3 s, a scare's in the same frame as its stinger. A bark whose speaker is in the level's `voices` (`{speaker: {label, side}}`) or whose line has `[side=]` shows at that screen edge with an arrow and the source label instead of a bubble.
- **Text on screen:** at 1280x720 dialogue and captions are 30 px, bubbles 28 px, name tags and choices 26 px (times 0.85 / 1.0 / 1.2 / 1.4 with the text size). Captions and bubbles sit on a box as wide as their longest line (up to 80% and 40% of the screen), and Korean wraps only between words. Captions sit right above the dialogue window when it is open, otherwise above the timecode; a bubble moves up out of a caption's way.
- **Controls screen:** pick an action, then press a key, a gamepad button or push a stick or trigger. If another action used it, the two swap. Esc or a mouse click cancels; Esc cannot be bound. "Reset to defaults" restores every binding. Menu keys (Enter, Esc, arrows, the bottom and right buttons) are fixed so menus always work. Bindings are saved in the `[input]` section of `user://proto_settings.cfg`.
- **UI strings:** labels come from `assets/original/ui/strings.csv` (`ui.options.*`, `ui.input.*`, `ui.pad.*`). A string can name a key with an action in braces (`{board}`, `{accept}`, `{interact}`), filled in as `[B]` or `[Select]` for the current device.

## Level file (`proto_level.json`)

| Key | Meaning |
|---|---|
| `size`, `player_start`, `water` | Level size, start position, water line (visual; `gaps: [[x0, x1]]` leaves room for rising-water zones) |
| `rising_water` | Zones `{x0, x1, track, base_y, linear_y, rate, max_rise, bark, bark_rise, submerge, respawn}`: on `track` (default `hifi`) the water climbs `rate` px/s while the player stays inside and falls back when they leave; on other tracks it stands at `linear_y`. Going under puts the player at `respawn`. `bark` is shown once the rise passes `bark_rise`. With `after_event` and/or `requires` the zone floods only once those hold (for example a path that is under water in HI-FI after 01:40 in a later chapter; use `rate: 0` and a `base_y` above the ground) |
| `solids`, `hifi_only`, `linear_only`, `ladders` | `[x, y, w, h]` rectangles. Track-only shapes exist only in that track. An optional fifth element names the art `tiles` entry for that one shape (for example `"room_floor"`) |
| `npcs`, `labels` | Markers and text drawn on the level; an NPC's optional `sprite` names an entry of `art.npcs` |
| `tape` | `length`, `time_scale`, dubbed `segments`, timeline `events` (`at`, `name`, `flag`). `slow: [{requires, scale}]` changes the tape speed while the flags hold (the last matching rule wins), for example a quarter-speed stretch |
| `darkness_event`, `darkness_alpha` | Event that darkens the screen |
| `tracks` | Flags that unlock HI-FI and MIX. `locks: [{requires, allow}]` keeps the player on the `allow` tracks while the flags hold (the key shows `ui.deck.held`, "Can't switch to <TRACK> now"); a trigger's `set_track` ignores locks and unlocks |
| `hub` | Workroom between loops: `start` and `between` dialogues (or `{"doc": id, "requires": [...]}` to collect and show a document found in the workroom), `scares` that precede a dialogue, `on_play` dialogue + scare before the tape starts, `start_docs` (a document shown before anything else, such as a content warning), `actions` (`[{key, dialogue, requires, prompt, bot}]`: a key that opens a dialogue in the workroom between tapes, such as closing out the job early; its `prompt` UI string is listed in the workroom text while it is available; the bot uses an action once only if it has `bot: true`), `save_point` (`{key, prompt, requires}`: the workroom's save point, listed with the actions once per visit; default prompt `ui.hub.save`) |
| `save_points` | Tape save points `[{id, rect, prompt, notice, requires, from, to, track, after_event}]`: standing inside one where no trigger wants the interact key shows `prompt` (default `ui.prompt.save`); interact saves a checkpoint (the counter, the player's place, the story so far) to the save file and shows `notice` (default `ui.save.checkpoint`). Being caught later in the same play goes back to the checkpoint instead of rewinding the tape. A save point rests once used until the player steps out of it. Marker art: the art block's `save_point` |
| `affinity` | `{"people": [{id, flag, speaker, alias, portrait, min, max, met}]}`: how people feel about the player. The story raises and lowers `flag` (`set save.aff_<id> += 1` in a choice); each change shows an up or down notice (`ui.affinity.up` / `ui.affinity.down` with the speaker's display name) and the value is kept within `min`..`max` (default -3..3). Threshold events are dialogues that require a value (`@requires save.aff_<id> >= 2`), started by an ordinary trigger or hub entry; `requires` lists in the level also take `"flag>=2"`, `"flag<=-1"`, `"flag>1"`, `"flag<0"`. The pause menu's People page lists everyone met (any `met` flag on, or the affinity moved) with their portrait and, for people with a `flag`, a gauge. A person without `flag` is shown for the portrait only |
| `story_algorithm` | Roles and random events picked from affinity (`scripts/proto/proto_story_algo.gd`, tested in `tests/godot/test_story_algo.gd`). `roles`: `[{name, pick, people, min, max, default, freeze}]`, re-picked from the `affinity` values every frame and written as the text flag `save.role_<name>` (read in the story as `save.role_helper == "keeper"`, in the level as `"save.role_helper=keeper"`). `pick` is `highest` (the highest value at or above `min`), `lowest` (the lowest at or below `max`) or `first` (the first person within bounds; a person may be `{id, min, max}` with bounds of their own); a tie goes to the earlier person, nobody within bounds gives `default` (`none` if unset). While a `freeze` condition holds the role keeps its value (for example during a scene that depends on it). `random`: `{seed_flag, prefix, pools: {"tape": {draw, events}, "hub": {draw, events}}}`; the tape pool is drawn as each play of the tape starts, the hub pool on each workroom visit. Each event `{id, weight, weights, group, requires}` weighs `weight` (default 1) plus each `weights` factor times its key's value (a flag's number, true as 1, or a condition such as `"!save.role_villain=dub"` as 1 or 0); events whose `requires` hold and that weigh more than 0 are drawn without putting back, at most one per `group`, and turn on `loop.rand_<id>` (`prefix`). Triggers and hub entries read those flags. The seed (`save.rng_seed`, picked once per new game; `-- --seed N`, 1 for bot runs and reels) with the loop number and pool name fixes each draw, so loading a save cannot draw again. The bot fails if a role was never picked or nothing was ever drawn |
| `journal` | Journal sections: `{"tabs": [{"label": UI string key, "categories": [document categories]}]}`; a tab without `categories` lists every collected document. Without the block the journal has one "All" tab. Found times and read marks are kept in the save's `journal` entry |
| `board` | Optional deduction board (B in the workroom): `requires` (flags that must be on), `art` (`sheet`, `frame`: a 320x180 board picture shown full screen) and `cards` `[{flag, doc, tc}]`. A card is pinned once its `flag` is on; its title and text come from the story document `doc` (category `board` by convention) and `tc` (tape seconds) is printed on the card and pinned on the timecode axis. Optional rows: `knots` `{requires, slots: [{flag, doc}]}` lights the seven knot slots as their flags turn on (the doc's title says what the knot is, its text shows once untied), and `conclusions` `{requires, slots: [{flag, docs}]}` shows the chosen answer of each conclusion (an integer flag value n shows `docs[n - 1]`). Up/Down change the row. The layout follows `assets/original/mibangsong/art/fx/mbs_ui_board.png` (axis 01:19 to 01:59, seven knot slots, five card slots that scroll, three conclusion slots) |
| `triggers` | `id` plus conditions (`rect`, `from`/`to` tape seconds, `track` (`hifi` / `linear` / `mix`), `loop`, `after_event`, `requires`: flags that must be on, `"!flag"` for off, `"flag=value"` to compare a number flag, `seen.*` allowed; the same list works wherever a block takes `requires`) and one action: `dialogue` (list, first available), `cue` (`hifi`/`linear`), `bark` (a pool id, or a list: the first pool whose conditions hold speaks, for example one pool per role), `doc` (collects it and opens the document viewer), `scare`, `rec_flag` (needs REC), `set_flag`, `warp` (`[x, y]`: moves the player, for example through a door into a room built elsewhere in the level). Options: `interact` (fires on Enter/E inside the rect, with the `prompt` UI string key; no prompt while none of its dialogues can start), `mark` (flag set when it fires, for once-only triggers with `requires: ["!flag"]`), `sfx` (named sound), `repeat` (fires again in the same loop, for doors), `set_track` (`hifi` / `linear` / `mix`: switches the track before the action, for a tape that slips by itself). `end_loop` ends the loop (the tape rewinds to the workroom), for example once the story has reached the end of the tape. A trigger fires at most once per loop unless it has `repeat`. When a scare ends, `loop.scare_done_<id>` turns on, so a trigger can wait for it |
| `rules` | `{"all": [flags], "set": flag}`: turns a flag on once all the others are on (for example six lanterns hung) |
| `chaser` | Pursuer that starts after the listed scares in LINEAR and triggers `catch_scare` when it reaches the player. With `start_flag` it starts once per loop when that flag turns on (no dialogue running), `start_offset` pixels from the player (default -360); `stop_flag` sends it away. It holds still while a scare is on screen (from onset to end), so a player startled by one is not caught for it. `modifiers`: `[{requires, speed, start_offset, hold}]` checked as a chase starts: the speed factors of all that hold multiply, the last `start_offset` wins and it waits the longest `hold` seconds before it moves (for example a helper who holds it back, a villain who drives it on) |
| `escorts` | `[{id, path: [[x, y], ...], speed, max_gap, requires, sprite: {sheet, frame, scale}, ribbon: {color, width}, done_flag}]`: something that moves along `path` while the requirements hold and the player keeps within `max_gap` pixels of it (it waits otherwise, and while dialogue runs). The path is drawn as a ribbon. At the end it sets `done_flag` |
| `title` | `{text, sub}`: the title screen's two lines (the menu words come from the UI strings `ui.title.*`) |
| `end_flag`, `report_flags` | Flag that ends the slice; flags printed by the bot |
| `end_docs` | `[{doc, requires}]`: when the end flag turns on, the first document whose flags hold is shown before the end (an ending's card) |
| `credits` | `{doc, secs}`: after the end documents, the document's title and paragraphs scroll up the screen as end credits (Enter or Esc skips). The words come from the story, not the code |
| `bot_route` | Optional `{from, to, x}` windows the bot walks to (smoke test); a window can also set `track`, `ff` (tape speed) and `requires`, and `follow` (an escort id) instead of `x`. The last matching window wins |
| `bot_prefer` | Choice line ids the bot takes whenever they are offered and enabled (for example the route to one ending); otherwise its usual rule applies |
| `bot_ff`, `bot_max_frames`, `bot_loops`, `bot_patrol` | Bot tape speed (default 20), frame limit, loop limit, and `[x_min, x_max]` for wandering outside route windows |
| `art` | Optional pixel art (next section) |
| `audio` | Optional sound ("Audio block" below) |

## Saves

The game saves only at save points (no autosave): the workroom's (`hub.save_point`, a workroom action) and the tape's (`save_points`, which also act as checkpoints). A workroom save comes back to the workroom; a tape save starts the tape again at that save point, with the counter, the track, the player's place, the triggers and timeline events already passed, and the story state of that moment. Progress since the last save is lost when the player quits or goes back to the title. The save holds the story state (`StoryRunner.serialize_save()`: loop and save flags, seen marks and collected documents, one-time choices, the loop count), the track and the journal, in `user://proto_save.json` (Godot's user folder for the project "Story prototype"; delete the file to start over; format 2, and a format 1 file from the old workroom autosave loads as a workroom save). `meta.*` flags (endings seen) stay in `user://meta.dat`, apart from the save.

Bot runs and reels skip the title and keep their save in memory, so they never touch the player's file. The bot uses the workroom save point once and every tape save point it walks through; at a workroom visit after its first play it saves, loads that save again and fails the smoke test if the story state does not come back unchanged. Caught after a checkpoint, the bot goes back to it at most once per play (a player can go back as often as they are caught).

## Meta outputs

Lines with a meta target (`os_dialog`, `window_title`, `desktop_file`; see `docs/script-format.md` 6.3) are shown with stand-ins drawn inside the game: a system window with an OK button, a title bar along the top of the screen, and a journal note in the lower right. The runtime picks the stand-in when the player has not allowed meta effects (`sys.meta_os`); when they have, the prototype also changes the real window title and still draws the other two inside the game. The stand-ins' own labels come from `assets/original/ui/strings.csv` (`ui.dialog.ok`, `ui.journal.added`).

## Art block

Paths are relative to the repository root. `build_prototype.py` copies every `.png` and `.pal` the block names into the build, copies `shaders/`, and writes `assets/art_atlas.json` with each sprite sheet's frame size, columns and frame names, read from the pixel-art sources in `assets/original/art/src/` and `assets/original/mibangsong/art/src/`. Frames are referred to by name. A missing file stops the build; a missing frame fails the smoke test.

| Key | Meaning |
|---|---|
| `zoom`, `camera_offset_y` | Camera zoom for the world (the art is drawn for a 320x180 screen, so 4 at 1280x720) and the camera's height above the player |
| `base_palette`, `palettes` | The `.pal` the art is drawn with and the per-track palettes (`linear`, `hifi`). Art drawn with the base palette is recoloured with `shaders/palette_swap.gdshader` when the track changes. With both palettes, MIX shows two pictures at once (`shaders/track_mix.gdshader`): the world is drawn a second time into a view that shares it, HI-FI-only shapes and props appear only in that view and LINEAR-only ones only in the main one, and the two alternate in a checkerboard of art pixels with the HI-FI picture pushed right and recoloured with the HI-FI palette. Without the shader, MIX draws the world halfway to the HI-FI palette and both tracks' shapes half transparent |
| `mix` | `{"shift"}`: how many art pixels the HI-FI picture is pushed to the right in MIX (default 3) |
| `vhs` | VHS texture over the world, below the UI (`shaders/vhs.gdshader`): scanlines on the 180 art rows, colour that smears and trails behind brightness, grain, and a tracking band rolling down the picture. On whenever the block or a `viewfinder` is present; `enabled: false` turns it off. It goes away for good once `off_flag` is on (default: the viewfinder's `off_flag`, the camera switched off). `scanlines` (at most 0.08: scanline contrast above 10% fails photosensitivity checks), `chroma`, `chroma_blur` (art pixels), `noise` and `band` tune it. With reduced flashing (P or the settings) the grain stands still and the band and the scanlines are gone |
| `backdrop` | `texture` (320x180) scrolled behind the level with `parallax` |
| `hub_backdrop` | Full-screen picture for the workroom between loops |
| `cuts` | `{dialogue_id: {"texture", "frame"}}`: a picture shown while that dialogue plays (a care home, a 1979 recording, a long take), fitted above the dialogue window on a dark background. Optional `when: [{from_line, requires, texture, frame}]` changes the picture halfway: the last entry whose line has been shown and whose flags hold wins, checked on every line (a close-up after the wide shot; the same shot once the camera is switched off). `requires: ["sys.gore"]` picks a graphic picture only while Graphic Content is shown; put the veiled picture in an entry for the same line just before it. An entry (or the cut itself) with `none: true` shows no picture; `frames: [names]` with `fps` loops several frames of the texture (a counter ticking over); `text: {rect: [x, y, w, h], size, color, fill}` writes the text of the entry's own `from_line` on the picture, in the picture's pixels (`fill` first covers whatever the art drew there, for example placeholder lines where a headline goes) |
| `tiles` | `sheet` plus frames for `solid`, `hifi_only`, `linear_only`, `water` (`[top, fill]` or one frame) and `ladder`. Extra entries name tiles for single shapes; an entry can be `{"sheet", "frames"}` to take tiles from another sheet |
| `props` | Decoration: `{"frame", "at": [x, ground_y]}` or a tile block `{"block", "w", "h", "at"}` (frames `<block>_<col>_<row>`); optional `sheet`, `repeat` and `step` (copies side by side), `track` (`hifi` / `linear`), `flag` / `unless_flag` (shown only while a flag is on / off, for example a lantern before and after it is hung; a prop with both `track` and a flag still hides on the other track), `scale` (around the bottom-left point, for small items), `recolour: false` (keeps the art's own colours under the track palettes) |
| `player`, `npcs`, `chaser` | Animated sprites: `{"sheet", "fps", "anims": {"idle": [frames], ...}}`. The player uses `idle`, `walk`, `jump`, `climb` and `caught`; the chaser `idle` and `lunge` |
| `viewfinder` | Camera overlay `sheet` with `rec` and `standby` frames; the live timecode is drawn over it. With `off_flag`, the overlay, timecode, track badge and VHS texture disappear and REC stops once that flag is on (the camera switched off for good) |
| `badges` | Track badge frames (`linear`, `hifi`, `mix`) |
| `scares` | Per scare id: `{"sheet", "frame", "anchor": "left" / "right" / "center" / "full", "min_seconds"}`, shown at the onset for the scare's body duration. Without an entry the scare is sound only |
| `ui` | Nine-slice panels `{"sheet", "scale", "window", "nametag", "choice", "paper": {"frame", "margin", "padding"}, "cursor": frame}` for the dialogue window, speaker tag, selected choice, choice cursor and document paper, enlarged `scale` times. Text is always drawn at runtime |
| `voice_wave` | `{"speakers": [character ids], "color"}`: a soft waveform above the dialogue window while those speakers talk (for voices with no body on screen) |
| `portraits` | `{"sheet", "speakers": {"<speaker>" or "<speaker>.<alias>": frame}, "dialogues": {"<dialogue id>": {"<speaker>[.<alias>]" or "*": frame or ""}}}`: the speaker's portrait (64x64 frames of `sheet`) on the left of the dialogue window, enlarged a whole number of times to about a fifth of the screen height. `dialogues` comes first (a person shown at another age, or `""` for a voice heard on a recording); `""` shows no portrait. Without the block a character file's own portrait (`portraits` in `character.json`) is used. Also the People page's pictures |
| `save_point` | `{sheet, frame}`: the marker drawn at the foot of every tape save point |

The demo uses the generic art in `assets/original/art/`.

## Audio block

Paths are relative to the repository root and are copied into the build like the art. Without the block the prototype plays a generated noise bed and noise stingers.

| Key | Meaning |
|---|---|
| `ambience` | `linear` and `hifi` loops play together on the `Linear` and `HiFi` buses, which the track mixer crossfades and which send into `Ambience` (the bus the scare director ducks); `hub` plays in the workroom |
| `ambience_db` | Gain for the ambience players |
| `loops` | `{"file", "db", "from", "to", "until_event", "stop"}`: plays during that tape time, stops for good when the timeline event fires and then plays `stop` once (for example a generator cutting out) |
| `stingers` | Per scare id: a file played at the onset instead of noise, at `level_lu - 20` dB (files are normalized to a -1 dBFS peak, which stands for +20 LU over dialogue) |
| `sfx` | Named one-shots: a path, a list (one picked at random) or `{"file", "db"}`. The prototype uses `step`, `rec_on`, `rec_off`, `prepulse` (soft mode), `deck_play`, `deck_rewind` and `tape_start` |
| `step_interval` | Seconds between footsteps. Footsteps stop in the scare director's quiet window (a sound 30-500 ms before a startle stimulus weakens it) |
 Scare frames are the art's own; check them against the photosensitivity rules in [`docs/scare-director.md`](../docs/scare-director.md) (drawn area, no saturated red, one flash per scare).

## Reel (demo videos)

`-- --reel <file.json>` plays a scripted sequence of scenes instead of the game: title cards, the workroom, tape scenes at a given time, track switches, walking (or walking beside an escort), dialogues with their choices, documents, subtitle cues, scares, the deduction board and end credits. All visible words come from the reel file and the story; the step list is documented at the top of `scripts/proto/proto_reel.gd`. `prototype/demo/reel.json` is a short example for the demo story.

```
python3 tools/build_prototype.py --story demo --reel prototype/demo/reel.json            # headless check
python3 tools/build_prototype.py --story demo --reel prototype/demo/reel.json --movie reel.mp4
```

With `--movie`, Godot's movie writer records 1280x720 at 30 fps with sound (`.avi`; `.mp4` is converted with ffmpeg). It needs a display; on a server without one, `xvfb-run` is used when it is installed. A reel for the private story belongs in `private/` (for example `private/reels/`), since its title cards and scenes are story material.

## Bot

`--smoke` runs the game headless with `-- --bot`: it advances dialogue, picks the first enabled choice, keeps REC on, switches to HI-FI once unlocked and walks the level (or the `bot_route`). It opens the settings screen once, the journal and the dialogue log once there is a document (every section, one document read full size), and the board whenever something new is on it, and walks every row. Bot runs and reels keep `meta.*` flags (endings seen, a second playthrough) in memory only, so they neither read nor change the player's `user://meta.dat` and every run starts the same. In a choice menu it meets again (a menu that loops back, such as picking a knot and a card), it takes the next option it has not tried, then the last one, so a looping menu cannot trap it. It prints one summary line (with `board found/total` and `knots untied/total` when the level has a board) and fails on script errors, missing art or sound, and objects leaked at exit. Add `-- --bot --trace` when running Godot directly to print every trigger, dialogue, bark, scare and loop end with its tape time, and the story algorithm's role changes, random draws and chase modifiers; `-- --bot --seed N` draws the random events with another seed. Run `--import` on the build once first, as `--smoke` does, or the game's classes are not found. Falling below the level respawns the player on the last safe ground. The bot presses Enter/E at every prompt, so a `repeat` door on its path needs route windows (with `requires` on the door's `mark` flags) that do not walk it back through the door.
